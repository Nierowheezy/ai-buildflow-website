BuildFlow separates the files you own from the context it generates, keeping every decision durable and readable.

## Files you own

| File | Purpose |
| --- | --- |
| `buildflow/config.json` | Deterministic review, verification, branch, quality-gate, and Continuous Mode policy |
| `buildflow/project-plan.md` | Product problem, users, MVP, data, stack, monetization, and UI direction |
| `buildflow/build-plan.md` | Ordered checkbox list of feature-sized outcomes |
| `buildflow/context/coding-standards.md` | Project conventions and testing expectations |
| `buildflow/context/ai-interaction.md` | Review, communication, and workflow preferences |

## Generated context

| File | Generated by | Purpose |
| --- | --- | --- |
| `context/project-overview.md` | `/overview` | Compact project context derived from the plans |
| `context/current-feature.md` | `/feature`, `/fix`, or `/rollback` | One active buildable scope with steps and proof |
| `context/findings.md` | `/audit` | Findings ledger with durable IDs and statuses; open or fixed P0/P1 findings block completion |
| `context/review.md` | `/audit independent current` | Pending handoff or completed receipt tied to the exact checkpoint and spec |

Edit upstream plans and regenerate the overview instead of patching downstream context by hand.

## History

`buildflow/history/features/` and `buildflow/history/fixes/` store completed specs. `buildflow/history/rollbacks/` stores dated reversal records with the target archive and commit, reason, dependency review, and proof. The original feature archive remains in place, so history shows both what shipped and why it was later removed.

Each feature build keeps its own archive: `NN-name.md` for the first build, and `NN-name--build-2.md`, `--build-3.md`, and so on after completed rollbacks. The stable plan ID stays the same.

## Tool adapters

Codex and GitHub Copilot share project skills under `.agents/skills/`. Claude Code project skills live under `.claude/skills/`. OpenCode can use either tree, so it does not need duplicate skills under `.opencode/skills/`.

## State directory

| Path | Purpose |
| --- | --- |
| `buildflow/.state/manifest.json` | Installed version, selected adapters, and hashes for BuildFlow-managed files |
| `buildflow/.state/.gitignore` | Keeps temporary staging files and local backups out of git |
| `buildflow/.state/run.json` | Generated record of the active or most recent substantial command |
| `buildflow/.state/review-specs/` | Exact ignored spec snapshots used by local-only independent-review requests |
| `buildflow/.state/backups/` | Pre-update copies of managed files that were replaced or removed |

The updater owns workflow skills and managed state. It does not manage project plans, generated configuration, context, history, `AGENTS.md`, or `CLAUDE.md`.
